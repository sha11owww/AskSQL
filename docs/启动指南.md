## 二、填写 API Key（必做）

编辑 `backend/.env`，把这一行补上：

```env
LLM_API_KEY=你的百炼APIKey
```

当前配置用的是阿里云百炼（DashScope），Key 从这里申请：
https://bailian.console.aliyun.com/ → API-KEY 管理

`backend/.env` 现有配置（无需改动，仅供核对）：

```env
LLM_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
LLM_MODEL=qwen3.7-plus
EMBEDDING_MODEL=text-embedding-v4
EMBEDDING_DIMENSIONS=1024
RERANK_MODEL=qwen3-rerank
RERANK_BASE_URL=https://dashscope.aliyuncs.com/compatible-api/v1
```

> 说明：Embedding 和 Rerank 与 LLM 共用同一个 Key 和 Base URL，填一个就够。

**填完后必须重启后端**（脚本里 Ctrl+C 再重跑），因为配置在进程启动时读取。

## 三、日常启动方式

### 方式 A：一键脚本（推荐）

项目根目录已加了一个 `start.sh`：

```bash
bash start.sh
```

它会自动完成：选 Python 和 Node → 检查配置 → 起后端并等就绪 → 起前端 → 打印访问地址。按 `Ctrl+C` 会同时停掉两个服务。

### 方式 B：手动两个终端

**终端 1（后端）：**
```bash
cd backend
.venv/Scripts/python.exe run.py
```

**终端 2（前端）：**
```bash
cd frontend
../.node/node.exe node_modules/vite/bin/vite.js
```

### 方式 C：Windows PowerShell

```powershell
# 终端 1
cd backend
.\.venv\Scripts\python.exe run.py

# 终端 2
cd frontend
..\.node\node.exe node_modules\vite\bin\vite.js
```

## 四、环境说明（本次已修复）

### 修复内容：虚拟环境路径

`backend/.venv` 是从另一台机器拷过来的，内部的 Python 路径指向 `C:\Users\Administrator\Desktop\...`，导致虚拟环境无法使用。

已修正 `backend/.venv/pyvenv.cfg` 中的三行路径，指向本机的 `backend/.python311`。原文件备份为 `pyvenv.cfg.bak`。

**依赖无需重装**——149 个包都还在，修复后验证通过：

```
fastapi 0.116.1 / uvicorn 0.35.0 / langgraph 1.2.11
duckdb 1.5.5 / mcp 2.0.0 / sqlglot 30.17.0
```

### 前端为何不用 npm run dev

项目在根目录自带了一个 Node 运行时（`.node/`，v24.19.0），不依赖系统 Node。但通过 `npm` 包装层调用 vite 时会出现日志丢失、端口探测异常。**直接用 node 调用 vite 更可靠**：

```bash
../.node/node.exe node_modules/vite/bin/vite.js
```

如果你更习惯 npm，前提是系统已装 Node 20.19+，那时 `npm run dev` 是可用的。

浏览器打开 http://127.0.0.1:5173 ，用内置账号登录：

| 账号 | 密码 | 可见数据 |
|---|---|---|
| `admin` | `admin123` | 全部数据库 |
| `sales` | `sales123` | 仅 `ecommerce_ops`（52 张表） |

登录后可直接提问，例如：

- 查询本月各地区销售额
- 按客户等级统计本月销售额
- 对比本月各地区销售额和销售目标

### 首次查询会稍慢

第一次提问时后端要构建 Schema 索引（55 张表 / 422 字段 / 85 条关联），需要调用 Embedding 接口，会有几秒到几十秒的等待。索引建好后会缓存到 `backend/data/schema_store.json`，后续查询就快了。

也可以提前手动构建，登录 `admin` 后调用：

```bash
curl -X POST http://127.0.0.1:8000/api/schema/index/rebuild \
  -H "Authorization: Bearer <你的token>"
```

## 六、常见问题

**Q：端口被占用怎么办？**
```bash
# 查看占用进程
netstat -ano | grep -E ":5173|:8000"
# 强制结束（把 <PID> 换成实际进程号）
taskkill //PID <PID> //F
```

**Q：前端报 502 或页面空白？**
确认后端是否在跑（访问 `/api/health`）。前端只是代理，后端挂了前端就报错。

**Q：查询没反应 / 只能返回"无法完成查询"？**
多半是 API Key 没填或无效。检查 `/api/health` 的 `api_key_configured` 字段。

**Q：`source activate` 激活虚拟环境后报错？**
激活脚本 `activate` 里的 `VIRTUAL_ENV` 变量也指向旧机器路径。绕过方式：不用激活，直接用 `backend/.venv/Scripts/python.exe` 绝对路径。

**Q：想看启动日志？**
- 脚本模式下：`backend/server.log` 和 `frontend/server.log`
- 手动模式下：日志直接打在终端里
